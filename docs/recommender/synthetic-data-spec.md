# 상품 추천시스템 더미 데이터 생성 명세

작성일: 2026-11-03

상태: 초기 SQL 생성기 구현. 아래 비율과 확률은 실습용 가정이며 실제 쇼핑몰 통계가 아닙니다.
본 실습 규모는 사용자 10만 명, Product 1만 개와 90일간 행동 약 1,000만 건입니다.
[전체 계획](product-recommender-plan.md)의 개발 실행 규모에도 같은 규칙을 적용합니다.
수기 fixture는 같은 필드와 참조/시간 규칙을 따르되 20개 카테고리와 통계적 비율을 강제하지 않습니다.

## 상품 분류

각 상품은 아래 하위 카테고리 하나에 속합니다. 첫 데이터셋에서는 다중 카테고리를 사용하지 않습니다.
그룹별 상품 수를 먼저 배정하고 그룹 안의 다섯 하위 카테고리에 같은 수를 배정합니다.

| 상위 분류 | 하위 카테고리 | 상품 비중 | 본 실습 상품 수 |
|---|---|---:|---:|
| 전자기기 | 키보드, 마우스, 모니터, 헤드폰, 충전기 | 30% | 3,000 |
| 생활용품 | 수납용품, 청소용품, 조리도구, 침구, 욕실용품 | 25% | 2,500 |
| 의류 | 상의, 하의, 외투, 신발, 가방 | 25% | 2,500 |
| 식품 | 간편식, 음료, 과자, 견과, 조미료 | 20% | 2,000 |

- `productKey`는 `rec-product-000001` 형식의 고유 문자열이며 이후 DB slug로 사용합니다.
- 카테고리마다 용도 4종과 특성 4종의 허용 목록을 둡니다. 예를 들어 키보드는 사무/게임/휴대/입문과
  저소음/무선/소형/인체공학처럼 해당 분류에 맞는 값을 사용하며 상품마다 용도와 특성을 하나씩 고릅니다.
- 가격대 태그 3종, 가상 브랜드 20종과 카테고리별 용도/특성 조합으로 서로 다른 상품을 만듭니다.
  가격대는 카테고리 안의 상대 구분이며 모든 카테고리에 같은 금액을 적용한다는 뜻이 아닙니다.
- 이름은 카테고리와 주요 속성을 반영합니다. 번호만 다른 동일 속성 상품으로 목표 수를 채우지 않습니다.
  카테고리마다 최대 960개 조합 중 중복 없이 선택합니다. 생성 전에 유효한 속성 조합 수가 배정 상품 수
  이상인지 검사하며 부족하면 실패합니다. 개발/본 실습 규모의 카테고리별 최대 배정 수는 각각 60개/600개입니다.
- 상품 속성과 판매 가능 상태는 90일간 고정합니다. 신규 상품 출시와 가격 변동은 첫 버전에서 다루지 않습니다.
  기존 DB의 Product/SKU 관계는 유지하며 오프라인 파일은 Product 단위입니다.

가격대는 `budget`, `standard`, `premium`, 가상 브랜드는 `brand-01`~`brand-20`을 사용합니다.
용도/특성 태그는 아래 값을 사용하며 같은 의미의 태그는 카테고리를 넘어 공유합니다.

## 사용자 구성

`userKey`는 `rec-user-000001` 형식이며 실제 회원의 이름, 연락처나 계정을 복사하지 않습니다.
사용자별로 가입일, 활동 유형, 주 관심 카테고리, 보조 카테고리와 선호 태그를 배정합니다.

| 활동 유형 | 사용자 비중 | 본 실습 사용자 수 | 행동 경로 시작 가중치 |
|---|---:|---:|---:|
| 활동 없음 | 5% | 5,000 | 0 |
| 가벼운 이용 | 60% | 60,000 | 0.5 |
| 보통 이용 | 30% | 30,000 | 2 |
| 잦은 이용 | 5% | 5,000 | 8 |

활동 가중치는 해당 날짜에 가입한 상태인 사용자 사이에서 선택 확률로 정규화합니다. 사용자마다 같은 이벤트 수를
할당하지 않습니다. 활동 없음 외의 사용자도 확률적 선택 결과에 따라 행동이 없을 수 있습니다.

- 가입 시점은 시작일 이전/시작일 80%, 1~59일차 10%, 60~74일차 5%, 75~89일차 5%로 배정합니다.
  첫 집단의 `createdAt`은 데이터 시작 시각, 나머지는 배정 구간의 날짜를 균등 추출한 UTC 자정입니다.
- 활동 유형과 가입 집단은 각각 정해진 인원수로 만들고 독립적으로 섞어 배정합니다. 반올림이 필요하면
  최대 나머지 방식으로 총원을 맞추며 동률은 표의 순서를 따릅니다.
- 서로 다른 주 관심/보조 하위 카테고리를 고릅니다. 주 관심은 상위 분류 상품 비중과 그룹 내 균등 분포로
  추출하고, 보조는 주 관심을 제외한 같은 분포를 다시 정규화해 추출합니다.
- 관심 카테고리의 용도/특성 허용 목록에서 선호 태그 두 개를 뽑습니다. 카테고리 선택과 태그 선택은
  사용자가 겹치는 관심사를 갖게 하면서 완전히 같은 프로필로만 묶이지 않게 합니다.
- 60일차 이전에 가입한 활동 가능 사용자의 20%는 60일차에 주 관심을 다른 하위 카테고리로 바꿉니다.
  이전 주 관심을 보조로 바꾸고 선호 태그를 새 주 관심에서 다시 뽑습니다. 60일차 이후 가입자는 초기 취향을 유지합니다.
  변화 대상 인원수의 소수점 이하는 버리고 seed로 대상을 선택합니다.

숨은 취향, 활동 유형과 변화 시각은 생성기 전용 자료입니다. 모델은 공개 상품 속성과 그 시점까지의 행동만
사용하며 숨은 취향을 정답이나 사용자 특징으로 읽지 않습니다.

## 한 행동 경로의 생성

한 경로는 동일 사용자와 상품의 조회로 시작하고 선택적으로 장바구니와 구매로 이어집니다.
`journeyId`로 경로를 구분합니다. 같은 사용자가 같은 상품을 다시 살펴보는 경우에도 새 경로 ID를 사용합니다.

### 사용자와 상품 선택

1. 해당 날짜에 존재하는 사용자 중 활동 가중치에 비례해 한 명을 선택합니다.
2. 이전에 조회한 상품이 있으면 15% 확률로 최근 서로 다른 조회 상품 최대 20개 중 하나를 균등 선택합니다.
3. 재방문을 선택하지 않았거나 과거 조회가 없으면 다음 세 경로 중 하나로 상품을 선택합니다.

| 상품 선택 경로 | 확률 | 선택 방법 |
|---|---:|---|
| 취향 기반 | 70% | 주 관심 60%, 보조 25%, 나머지 15%로 카테고리를 고른 뒤 아래 태그 가중치로 선택 |
| 인기 기반 | 20% | 고정된 상품별 인기 가중치로 전체 상품 중 선택 |
| 무작위 탐색 | 10% | 전체 상품 중 균등 선택 |

나머지 카테고리의 15%는 주 관심과 보조를 제외한 카테고리에 균등 분배합니다. 취향 경로에서 상품의
가중치는 `1 + 2 × 일치하는 선호 태그 수`입니다. 같은 카테고리 안에서 이 값을 정규화합니다.
인기 경로는 seed로 상품 순서를 섞은 뒤 순위 r에 `1 / r^1.1`의 가중치를 주고 정규화합니다.
이 인기도는 생성기의 외생 가정입니다. 학습 모델의 인기 점수는 학습 행동에서 별도로 계산합니다.

### 조회에서 구매까지

선택된 상품의 선호 수준을 아래 순서로 판정합니다. 높은 조건이 먼저 적용됩니다.

| 선호 수준 | 판정 | 조회 후 장바구니 확률 | 장바구니 후 구매 확률 |
|---|---|---:|---:|
| 높음 | 주 관심 카테고리 또는 선호 태그 2개 일치 | 22% | 35% |
| 중간 | 보조 카테고리 또는 선호 태그 1개 일치 | 12% | 20% |
| 낮음 | 그 밖의 상품 | 4% | 8% |

- 최초 조회는 항상 생성합니다. 추가 조회는 0회 80%, 1회 15%, 2회 5%로 추출합니다.
- 장바구니는 경로당 한 번 추출하고 성공한 경로에서만 구매 여부를 한 번 추출합니다.
  조회 횟수만큼 장바구니 확률을 반복 적용하지 않습니다. 한 경로는 총 1~5개의 이벤트를 가집니다.
- 반복 조회의 간격은 10~120초, 마지막 조회에서 장바구니까지는 60~600초,
  장바구니에서 구매까지는 60~1,800초의 정수 균등 분포입니다.
- 첫 조회는 해당 UTC 날짜의 0~83,699초에서 균등 추출합니다. 최대 지연은 2,640초이므로 경로가
  자정을 넘지 않습니다. 이 제한으로 초기 버전은 장바구니 생성과 구매가 다른 날짜에 일어나는 행동을 생략합니다.
- 최근 조회 이력은 경로의 최초 조회에서만 갱신합니다. 경로 안의 추가 조회는 별도 선택 이력을 만들지 않습니다.
  경로 번호 순서와 최초 조회 시각 순서를 일치시켜 미래 경로의 상품이 과거 경로의 이력에 들어가지 않게 합니다.
- 기본 생성기의 구매는 즉시 확정된 합성 이벤트입니다. 장바구니가 없는 구매는 생성하지 않습니다.
  [주문/결제 확장](commerce-data.md)은 전용 DB에 대응하는 합성 주문, 결제와 재고 기록을 추가합니다.
  취소/환불은 별도 거래로 기록하며 원본 행동을 수정하지 않습니다. 실제 PG 요청이나 이메일은 발생시키지 않습니다.

## 시간과 이벤트 수

데이터 시간은 `2026-01-01T00:00:00Z`부터 `2026-04-01T00:00:00Z` 직전까지입니다.
이는 실습용 고정 시간축이며 사용자의 일정이나 실제 서비스 운영 기간이 아닙니다.
시작일을 바꿀 때도 90일 길이와 시작 기준 60/75일차의 학습/검증/테스트 경계를 유지합니다.

일별 목표는 해당 날짜에 존재하는 사용자들의 활동 가중치 합에 비례해 배정합니다. 주말에는 1.25배,
평일에는 1배를 곱하고 90일 전체에서 정규화합니다. 최대 나머지 방식과 날짜 오름차순 동률 처리로
일별 정수 예산의 합을 1,000만 건에 맞춥니다. 개발 실행은 같은 방식으로 100만 건을 배정합니다.

날짜마다 완전한 행동 경로를 생성해 예산에 도달하면 멈춥니다. 마지막 경로를 잘라 장바구니나 구매를
누락시키지 않습니다. 한 경로가 최대 5건이므로 90일 전체 초과분은 최대 360건입니다.
이벤트 수 목표는 모든 유형을 합한 값이며 구매 1,000만 건을 뜻하지 않습니다.

날짜마다 먼저 경로 번호 순서대로 사용자, 상품, 전환 여부와 상대 지연을 생성해 예산을 채웁니다.
가입과 취향은 날짜 안에서 변하지 않으므로 이 순서로 최초 조회 이력을 관리할 수 있습니다. 그날의 경로 수가
정해지면 같은 수의 시작 시각을 추출하고 정렬해 경로 번호 순서대로 배정합니다. 같은 시각은 경로 번호순입니다.
이후 개별 이벤트 시각을 계산하고 정렬합니다. 하루 단위 임시 자료만 유지하며 90일 전체를 메모리에 모으지 않습니다.

## 파일과 재현성

2026-11-03 사용자 요청에 따라 출력 형식을 SQL로 구현했습니다. 적재 방법은
[로컬 SQL 실행 안내](local-sql.md)를 따릅니다.

| 파일 | 모델에 제공하는 내용 |
|---|---|
| `dataset.sql.gz` | `rec_products`, `rec_users`, `rec_events`와 완료 표시 `rec_dataset`의 스키마/데이터 |
| `manifest.json` | 생성기 버전, seed, 시간 경계, 규모, SQL과 생성 소스 checksum |
| `summary.json` | 실제 행 수, 유형별/일별 분포, 경로와 전환 집계, 실행 시간, 최대 메모리와 SQL 크기 |

생성기 전용 사용자 프로필과 상품 인기 순위는 별도 `private/`에 보관합니다. 학습은 공개 실습 테이블만
명시적으로 읽습니다. `eventId`와 `journeyId`는 검증용 식별자이며 모델 특징으로 사용하지 않습니다.
이벤트 ID는 날짜 순회, 경로 번호와 경로 내 순번에 따라 증가하는 정수이며 일별 이벤트는 시각, eventId 순으로 정렬합니다.

seed뿐 아니라 생성기 버전, 난수 구현과 실행 환경을 고정합니다. 최초 구현은 단일 프로세스로 시작하고
순회 순서를 고정합니다. 압축 파일의 생성 시각 같은 비결정적 metadata도 고정해 같은 환경에서 파일을
재생성했을 때 내용과 checksum을 비교할 수 있게 합니다. 생성물은 Git에 넣지 않습니다.

## 생성 완료 검사

- 사용자/상품 수와 카테고리, 활동 유형, 가입 집단의 배정 수가 설정과 일치합니다.
- eventId가 유일하고 모든 참조가 존재하며 `createdAt <= occurredAt`입니다.
- 경로마다 최초 view, 선택적 반복 view, 선택적 cart, 선택적 purchase 순서를 만족합니다.
  cart와 purchase는 각각 최대 한 번이며 유형이 다른 이벤트는 시각이 엄격히 증가합니다.
- 이벤트가 90일 범위와 날짜별 transaction 경계 안에 있고 일별 예산 이상, 예산보다 최대 4건 많습니다.
- 모델에 제공하는 파일에 숨은 취향, 미래 구매 여부와 생성기의 선호 수준을 넣지 않습니다.
- 학습, 검증과 테스트의 이벤트/구매 수, 평가 시점에 존재하는 사용자 수와 신규 사용자 수를 기록합니다.
- 카테고리별/활동량별 고유 사용자-상품 쌍, 상위 1% 상품의 이벤트 점유율, 무행동 사용자 비율,
  구매 경험자와 고유 구매 쌍 수를 보고합니다. 같은 쌍의 반복 이벤트를 데이터 다양성으로 계산하지 않습니다.
- 경로 선택 비율과 선호 수준별 장바구니/구매 전환율을 실제 분모와 함께 보고합니다.
  확률과 관측 비율이 정확히 같아야 한다고 검사하지 않으며 작은 표본에서는 차이가 클 수 있습니다.

## 비교 시나리오와 해석

첫 생성은 위 기본 설정 하나로 진행합니다. 모델 비교 때는 다음 조건을 개발 규모에서 각각 바꿔 확인합니다.
조건 변경은 별도 데이터 버전으로 남기며 한 평가의 테스트 결과를 보고 같은 평가의 설정을 재선택하지 않습니다.

- 취향 신호 감소: 재방문 외 선택 비중을 취향 40%, 인기 20%, 무작위 40%로 바꿉니다.
- 인기 편중 증가: 기본 선택 비중을 유지하고 인기 순위 지수를 1.1에서 1.4로 바꿉니다.
- 취향 변화 없음: 기본 설정에서 60일차 취향 변경 대상만 0%로 바꿉니다.

카테고리와 태그로 행동을 생성하므로 속성 기반 모델이 유리할 수 있습니다. 모델 순위는 이 생성 가정 아래의
결과로 해석하며 실제 사용자의 선호나 온라인 효과를 입증하지 않습니다. 본 규모 실행 완료와 학습 이해도는
별개로 기록합니다. 실제 실행 시간과 메모리 한도는 생성기 구현 후 측정합니다.
